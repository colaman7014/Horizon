## [Nvidia 發佈 Nemotron 3.5 Lightning 與 NeMo Switchyard](https://blogs.nvidia.com/blog/nemotron-lightning-switchyard-rtx-dgx/) ⭐️ 8.0/10

Nvidia 發佈了 Nemotron 3.5 Lightning，這是一個 30B 參數的 Mixture‑of‑Experts 語言模型，每次推理僅啟用 3B 參數，同時推出了開源 NeMo Switchyard 庫，用於智能路由 LLM 流量至多個供應商。 這種高效的 MoE 模型與路由框架相結合，可實現低延遲、高吞吐量的代理式 AI 工作負載，同時降低 GPU 消耗，可能會改變對 Nvidia GPU 的需求並鞏固其在企業 AI 市場中的地位。 Nemotron 3.5 Lightning 在混合架構中交錯使用 Mamba‑2、MoE 和選擇性注意力層，而 Switchyard 是一個由 Rust 伺服器通過 PyO3 綁定支持的 Python 代理，能夠在 OpenAI 與 Anthropic API 之間進行翻譯並支援帶型別和配置文件的路由流程。

hackernews · droidjj · 8月11日 19:35 · [社群討論](https://news.ycombinator.com/item?id=49263340)

**背景**: Mixture‑of‑Experts（MoE）通過僅為每個輸入激活部分專家來擴展大型語言模型，從而在保持性能的同時降低計算量。代理式 AI 系統通常協調多個專門化模型以完成複雜任務，需要智能路由機制來為每個請求選擇最合適的模型。

## [LLM API 漏洞：竊取內部推理痕跡](https://stolen-thoughts.com/) ⭐️ 8.0/10

研究人員已經展示了一種提示工程技巧，能從 OpenAI、Anthropic 和 Google 等專有 LLM API 中提取推理鏈（CoT）痕跡，無需直接存取模型即可揭示內部決策過程。此方法包含四個攻擊向量，包括繞過反蒸餾機制與大規模私密資料擷取。 能夠竊取內部推理暴露了專有模型知識，削弱了智慧財產權保護，也可能被用於惡意蒸餾或規則迴避。投資者與安全團隊必須評估此類漏洞對 AI 服務信任度的影響。 此技巧利用提示注入與內部工具呼叫，迫使模型以可解析格式輸出其 CoT，然後重放或蒸餾；但需要精細的提示設計，且現行防禦（如反蒸餾標誌）對此方法尚無效。

hackernews · r/LocalLLaMA · quantumgarbage · 8月11日 13:22 · [社群討論](https://news.ycombinator.com/item?id=49257876)

**背景**: 推理鏈（CoT）提示能促使大型語言模型產生中間推理步驟，提升對複雜任務的表現。專有 LLM API 通常將這些內部狀態隱藏於黑盒介面，但研究人員已發現可透過提示工程逼迫其輸出。

## [Meta 面臨 1.4 萬億美元訴訟，Section 230 只作防禦](https://arstechnica.com/tech-policy/2026/08/meta-cant-stop-states-1-4-trillion-lawsuit-from-going-to-trial/) ⭐️ 8.0/10

聯邦法院裁定《通訊寬恕法》第 230 條僅提供訴訟防禦，而非免責。因而，Meta 無法阻止多州提出的 1.4 萬億美元訴訟進入審判階段。 此裁決使 Meta 面臨前所未有的法律風險，並可能為其他科技平台樹立先例，改變監管格局。它亦威脅 Meta 股價，或促使對 Section 230 的更廣泛審查。 第 230 條的語言歷來為平台提供對用戶生成內容的責任豁免，但法院強調它並未授予對州級訴訟的絕對免責。此裁決專門適用於多州提出的訴訟，指控 Meta 透過其平台促成非法活動。

rss · Ars Technica · 8月11日 20:27

**背景**: 《通訊寬恕法》第 230 條於 1996 年制定，旨在鼓勵網路平台對內容進行調節而不必擔心責任。它為第三方內容提供廣泛的民事訴訟豁免，但允許針對非法活動等例外情況。43 州提出的 1.4 萬億美元訴訟指控 Meta 未能有效監管極端及犯罪內容，要求賠償並推動法規改革。
