# Manual Schedule Backfill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute the existing local Horizon daily pipeline once to backfill the latest 24 hours and publish any generated documentation to `gh-pages`.

**Architecture:** Reuse `scripts/daily-run-local.sh` unchanged. The script starts OrbStack if needed, waits for Docker, runs the containerized Horizon pipeline with `--hours 24`, then publishes `docs/` through a temporary `gh-pages` worktree.

**Tech Stack:** Bash, OrbStack/Docker Compose, Horizon Python CLI, Git worktrees, GitHub `gh-pages` branch.

## Global Constraints

- Do not modify source code, `scripts/com.colalin.horizon-daily.plist`, or runtime configuration.
- Run exactly the existing `bash scripts/daily-run-local.sh` path from the repository root.
- Backfill only the latest 24-hour window; do not split dates or add historical replay behavior.
- Do not run destructive Git commands such as `reset`, `clean`, checkout over changes, or force push.
- Do not start a second copy if the same local script is already running.
- Do not automatically retry after a pipeline failure; preserve the failure output for diagnosis.

---

### Task 1: Execute and verify the approved one-time backfill

**Files:**
- Run: `scripts/daily-run-local.sh`
- Inspect: `data/`, `docs/`, and the generated `gh-pages` commit only through the script's existing behavior.
- Modify: none intentionally; normal pipeline output may update `data/` and `docs/`.

**Interfaces:**
- Consumes: existing `.env`, `data/config.json`, Docker/OrbStack, and Git credentials.
- Produces: a completed 24-hour Horizon report and either a pushed `gh-pages` update or an explicit no-change result.

- [x] **Step 1: Confirm there is no concurrent local run**

Run:

```bash
pgrep -af '[s]cripts/daily-run-local.sh' || true
```

Expected: no output. If a matching process is present, do not start another run.

- [x] **Step 2: Confirm the working tree has no unreviewed generated-file conflict**

Run:

```bash
git status --short
```

Expected: no uncommitted `data/` or `docs/` changes that the pipeline could overwrite. The run may proceed with unrelated reviewed changes, but it must not reset, clean, or overwrite them.

- [x] **Step 3: Run the existing full pipeline**

Run from the repository root:

```bash
bash scripts/daily-run-local.sh
```

Expected output includes:

```text
Starting Horizon daily run...
Docker is ready.
```

and ends with either:

```text
Published to gh-pages.
Done.
```

or:

```text
Nothing to commit.
Done.
```

A non-zero exit status is a failed backfill. Preserve the complete output and do not retry automatically.

- [x] **Step 4: Verify the resulting local output and publish outcome**

Run:

```bash
git status --short -- data docs
```

Expected: any local `data/` or `docs/` changes are the report generated by this run. The command output from Step 3 must already confirm either a successful `gh-pages` push or that there was nothing to commit.

- [x] **Step 5: Record the observed result**

Report the actual exit status, the final script status line, and whether `gh-pages` was updated. If Step 3 failed, report the failing stage and stop without claiming completion.
